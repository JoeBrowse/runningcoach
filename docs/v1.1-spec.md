# Skid Marks 2.1 specification: first open, hybrid week, setups

This document gives the decisions for version 2.1. It adds to `docs/v1-spec.md`. The training rules come from `docs/research/concurrent-training.md`.

## 1. First open

1. The intro animation (first launch only, as now).
2. **"What do you want to use Skid Marks for?"** Three large choices: **Running**, **Lifting**, **Both**. A note under them: "You can change this later in Settings."
3. **Tour.** Short cards that explain what the app is for, at a high level:
   - Running overview (2 to 3 cards): a plan that fits your week and changes when life changes; record runs with voice cues; progress and races.
   - Lifting overview (2 to 3 cards): log sets and see progress; programmes or a generated plan; the muscle readiness map.
   - "Both" shows both overviews, then one card about the shared week ("Runs and gym days are in one week. Each side respects the other.").
   - Each card has Next and Skip.
4. **"Your week."** Questions:
   - Which days can you train? (pick weekdays)
   - Running or both: how many days a week can you run?
   - Lifting or both: how many days a week can you lift?
   - Both: what matters most? Running, lifting, or both the same.
   - Both: "Can you train twice on one day?" (yes / no; default no).
   - The app proposes a week (see section 3) and shows it as 7 rows with a reason for each rule it applied. The user can change days. Save writes the master week.
5. The app then opens: Plan mode for Both, Run mode for Running, Lift mode for Lifting.
6. Users who upgrade with old gym data still go straight to Lift with no first-open flow.

The old "Who are you?" screen and its "Bring your history" step are removed from first open.

## 2. Setups on each mode page

- **Run page**: until running is set up, Run home shows a "Set up running" card. It opens the existing plan wizard without the questions that "Your week" already answered (run days, long-run day and gym days come from the master week). It still asks: goal (with or without a race), race date, goal time, current fitness (recent result, "use my past runs" or "I am new"), experience, units, optional heart-rate values, medical disclaimer.
- **Lift page**: until lifting is set up, Lift home shows a "Set up lifting" card:
  1. Level: Beginner, Intermediate or Advanced.
  2. "Enter my current plan" opens the existing programme builder (`ProgrammeBuilderScreen`), or "Make a plan for me" opens the existing guided wizard (`GuidedProgrammeWizard`). The wizard is pre-filled from the level, the lift days of the master week and the split from section 3.
  3. The result is saved as the active programme, as now.
- A mode that the user did not choose (for example Lift for "Running") still shows in the mode switch, with its setup card, so the user can start it later. Settings has "I use Skid Marks for: Running / Lifting / Both".

## 3. The hybrid week (engine)

`planWeek(input)` in `src/run/engine/week.js`, exported from `src/run/engine.js`.

Input:
```
{
  use: 'run' | 'lift' | 'both',
  availableDays: [0..6],          // 0 = Sunday
  runDays: number,                // how many runs a week (0 for lift only)
  liftDays: number,               // how many lift sessions a week (0 for run only)
  priority: 'run' | 'lift' | 'equal',
  doubles: boolean,               // two sessions on one day allowed
  runLevel: 'new' | 'some' | 'experienced',
  liftLevel: 'beginner' | 'intermediate' | 'advanced',
  longRunDay: number | undefined, // optional preference
}
```

Output:
```
{
  runDays: [0..6],                // the days with a run
  longRunDay: number | null,
  gymDays: [{ day, type: 'upper'|'lower'|'full'|'legs', intensity: 'heavy'|'light', note }],
  doubles: [{ day, first: 'run'|'lift', gapHours: 6 }],
  restDays: [0..6],
  split: 'full' | 'upper-lower-upper' | 'upper-lower' ,
  reasons: [string],              // STE sentences, one per rule applied
  warnings: [string],             // for example "Too many sessions for your days. We reduced lifting to 2."
}
```

Rules (from the research note): heavy legs or lower never the day before (and not within 48 h before) a quality run, and not within 72 h before the long run; upper body can share a day with an easy run, but only when doubles are allowed ("no" is firm); doubles priority first, gap of 6 hours or more; at least one rest day (two for a new runner or a beginner who only lifts; a new lifter who runs keeps one and starts with light sessions); runs spread over the week (no 3 runs in a row and no run the day after the long run for a new runner when the days allow it); the priority decides between heavy legs and room for a hard run; split by lift days (1-2 full body, 3 upper/lower/upper, 4 upper/lower/upper/lower only with lifting priority); if the sessions do not fit the available days, reduce the lower-priority side first and say so in `warnings`. Also `recommendWeek({use, runLevel, liftLevel, priority})` returns default counts from the "Starting weeks" table.

The plan engine (`buildPlan`) keeps taking `runDays`, `longRunDay` and `gymDays` as now.

## 4. Unplanned sessions and how-I-feel buttons (engine + UI)

New `adapt` event types in `src/run/engine/adapt.js`:

- `{ type: 'unplannedSession', kind: 'run' | 'lift', date, intensity: 'easy'|'hard'|'long', areas: ['legs'|'upper'|'full'], minutes }`:
  - Unplanned heavy legs or full body: the next hard run or long run within 48 h (72 h for the long run) becomes an easy run or moves to a safe day, with a reason.
  - Unplanned hard or long run: the next hard run within 48 h becomes easy; a heavy leg day next day becomes light, with a reason.
  - Unplanned easy run: the week counts it; the next easy run in the next 2 days gets shorter (not below 3 km or 20 min), with a reason. No change if the week is under its target.
  - Unplanned upper-body lift: no run change. If a planned upper session is within 48 h, mark it light, with a reason.
  - It never breaks a safety rule. It returns `changes` with reasons, like the other events.
- `illness`, `injury`, `readiness` and a new `{ type: 'tired' }` (the "I feel really tired" button) also act on gym days: rest or light, with reasons. `tired`: today's hard run or heavy lift becomes easy or light; the next day stays easy.

UI: when a run or a lift session is saved on a day that has no plan for it, the app calls `applyEvent({type: 'unplannedSession', ...})` and shows a short "Plan updated" notice with the changes and Undo. "I feel really tired" joins the "Something changed?" chips.

## 5. Strava import removed

The Strava bulk export import (ZIP with `activities.csv`) and the Strava help text are removed. GPX, TCX and FIT file import stay on the Data screen. The plan wizard's "use my past runs" uses runs recorded in the app and imported files.

## 6. Tests

- Engine: `planWeek` for every use, level, priority, day count and doubles setting: every rule in section 3 holds; reasons are present; nothing is planned on an unavailable day. `unplannedSession` and `tired`: the next sessions change as in section 4, and every safety check still passes.
- UI: first open for Running, Lifting and Both; both setups; an unplanned lift and an unplanned run on a planned week; "I feel really tired".

## 7. Version 2.4: a simpler Plan and Run (Run in beta)

The owner uses Lift every week and wants Plan and Run to stay simple: pick the gym days and the programme, pick the run days, set a goal (for example a half marathon), and run with voice cues for a pace range on the watch.

- **Your week** asks four things: the lift days, the programme (full body, upper and lower, or push, pull, legs), the run days and the long-run day. The user picks the days; the app does not. `weekSetup.weekFromPicks` places the leg days away from the long run (never on it, the day after it or the 2 days before it) and makes a leg session light when no safe place exists, with a note. A run and a lift on one day: run first, 6 hours or more between them. `engine.planWeek` stays in the engine for a later "Suggest a week" button.
- **Run setup** shows 6 goals (run/walk to 5K, 5K, 10K, half marathon, marathon, keep fit), no heart-rate fields, and "Coach me by: Pace / Feel" (`profile.coachBy`). Pace shows pace ranges on the run screens, in the voice cues and on the watch, also in Simple mode (`runData.paceOn`).
- **Plan home**: the setup steps (your week, then your goal), today, four change chips (missed, ill, really tired, something hurts) and "More changes", this week, and links to your week, your goal, all weeks and the change history.
- **Run home**: a Beta banner, today's run, Something changed, and three links (plan weeks, progress, watch and data). The other run screens stay in the code with no link.
- **Beta label** on the Run tab of the mode switch and in first open.
